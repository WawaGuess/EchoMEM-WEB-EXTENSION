# ADR-008: 单分支构建公网版与内网版发行包

## 状态

Implemented

## 背景

EchoMem Web Extension 的公网用户与内网用户完全分开，且两类用户访问不同的 EchoMem 服务地址。原先统一预置 localhost 只适用于开发机，正式用户必须手动修改，容易选错网络环境或遗漏协议和端口。

公网版和内网版的功能、权限、接口及发布节奏相同，差异仅为默认服务地址和发行包标识。为该差异维护两个长期分支会导致修复、文档和已提交 bundle 漂移。

## 决策

仓库只维护一个源码分支，在构建阶段选择 `public` 或 `intranet` 发行配置：

| 发行类型 | 默认服务地址 | 输出目录 |
|---|---|---|
| 公网版 | 构建时读取 `ECHOMEM_PUBLIC_BASE_URL` | `release/EchoMem-Extension-Public/` |
| 内网版 | 构建时读取 `ECHOMEM_INTRANET_BASE_URL` | `release/EchoMem-Extension-Intranet/` |

真实地址不得硬编码或提交到仓库。构建脚本从环境变量读取发行地址，校验为不含凭据、查询参数和片段的 HTTP(S) 绝对 URL，再将发行类型、展示名称和默认服务地址注入 content-script bundle。每个 bundle 只包含自身的服务地址。配置读取继续以 `chrome.storage.local.echomemConfig` 为最高优先级，因此升级扩展不会覆盖用户已保存的地址。

`npm run build` 生成不含真实服务地址的开发版 `dist/`；设置两个环境变量后，`npm run package` 独立构建并校验两个发行目录。GitHub Release 从同名 Actions Secrets 注入地址并同时发布两个 ZIP。地址发生变化时更新 Secret 并重新发布，不修改代码。

认证密钥不属于发行配置，不得写入源码、bundle、manifest 或发行说明。

## 备选方案

### 两个长期分支

拒绝。服务地址常量不足以支撑分支分叉，长期合并会增加修复遗漏、生成产物冲突和发布不一致的风险。

### 单包提供内外网选择器

暂不采用。当前两类用户完全分开，分别分发发行包可以减少首次配置步骤，也避免公网包包含内网地址。

### 继续预置 localhost 并要求用户手动填写

拒绝。localhost 指向运行浏览器的设备，不代表统一部署的 EchoMem 服务，不能作为正式发行默认值。

## 影响

- 发布流程必须同时生成和校验两个发行包。
- 配置面板会显示当前发行类型，并预填相应地址。
- 用户保存过的地址继续覆盖构建预置值。
- 公网发行地址应使用 HTTPS；若配置 HTTP，`X-Auth-Key` 会通过明文 HTTP 传输。
- 本地手动加载仓库根目录时使用开发版 `dist/`，需手动填写服务地址。
