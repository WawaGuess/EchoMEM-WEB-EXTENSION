# 工具栏打开网页浮层流程

> 相关代码：`background.js`、`src/services/messaging.js`、`src/core/router.js`
> 架构决策：`docs/decisions/007-扩展入口统一为网页浮层.md`

## 调用链

```text
用户点击扩展工具栏图标
        ↓
chrome.action.onClicked
        ↓
chrome.tabs.sendMessage(activeTabId, {
  action: "openEchoMemOverlay"
})
        ↓
Content Script 确认平台已识别
        ↓
ensureEchoMemOverlayOpen()
        ↓
已有可见 overlay？── 是 ──> 保持当前实例和路由，不重复创建
        │
        否
        ↓
openEchoMemHomePanel()
        ↓
使用现有 panelHost.overlayConfig 创建网页 overlay
```

工具栏没有 `default_popup`，因此点击事件由 Background Service Worker 直接处理。

## 与网页入口的关系

HIGO 标题栏的“图形 + EchoMem”组合标和工具栏消息都通过 `ensureEchoMemOverlayOpen()` 进入。连续点击不同入口时，如果 overlay 已存在，则返回 `{ opened: false, alreadyOpen: true }`，不会重建面板、遮罩或关闭事件。聊天输入框附近不再注入 EchoMem 按钮。

## 失败场景

以下页面无法打开 overlay，Background 只记录警告，不注入额外常驻界面：

- 浏览器内部页面，无法加载 Content Script；
- 页面尚未完成扩展脚本加载；
- 当前页面未被识别为支持平台。

## 不变范围

- `src/core/panel-host.js` 的 overlay 创建与关闭逻辑；
- `src/core/router.js` 的首页和功能路由；
- 输入联想、资源插入和会话录制对平台输入框的使用；
- overlay 内六项功能的页面与业务行为。
