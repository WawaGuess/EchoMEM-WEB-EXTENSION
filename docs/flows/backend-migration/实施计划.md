# EchoMem 后端迁移完整实施计划

> 本文档是 `docs/decisions/005-后端迁移至EchoMem.md` 的配套执行计划，按三期详细说明每一步的任务、改动文件、验收标准和风险点。
> 
> 接口对照与现状说明：`docs/reference/EchoMem后端迁移现状与接口对照.md`

## 总体原则

- 彻底切换：代码中不再保留 OpenViking 专用逻辑，用户侧统一使用"记忆后端引擎"文案。
- 分阶段实施：优先保证核心记忆链路可用，再改造资源/Skill，最后接入统计。
- 配置简化：`echomemConfig` 保留 `baseUrl`、`authKey`，**新增可选 `agentId`**。未填写时默认使用 `echoagent`；服务地址由发行类型预置，构建时分别从 `ECHOMEM_PUBLIC_BASE_URL`、`ECHOMEM_INTRANET_BASE_URL` 注入，用户已保存配置优先。
- 按平台使用 `agent_id`：未配置时所有平台默认 `echoagent`，可在配置面板按需要修改（例如 HIGO 数据写入 `higo_agent` 时，面板填 `higo_agent`）。
- 一期保留旧 `openviking-client.js`，二期完成资源/Skill 改造后再删除。

### 接口映射

| 功能 | 原接口 | 新接口 |
|---|---|---|
| 健康检查 | `GET /health` | `GET /health` |
| 记忆召回 | `POST /api/v1/search/find` | `POST /api/retrieval/search` |
| 创建会话 | `POST /api/v1/sessions` | `POST /api/sessions/open` |
| 追加消息 | `POST /api/v1/sessions/{id}/messages` | `POST /api/sessions/{id}/messages` |
| 提交会话 | `POST /api/v1/sessions/{id}/commit` | `POST /api/sessions/{id}/commit` |

### 关键实现点

1. **认证头**：所有请求附加 `X-Auth-Key: ${authKey}`，JSON 请求附加 `Content-Type: application/json`。身份（tenant_id / user_id）由 `X-Auth-Key` 推导，**请求体中禁止携带 `user_id` 或 `tenant_id`**，后端会显式拒绝。
2. **响应解析**：EchoMem 返回 `{status, result}` 或 `{error, message}`，需统一处理。
3. **agent_id**：从调用方传入，不要写死在 client 中。
4. **错误兼容**：保留现有的超时、认证失败、连接失败提示文案。
5. **调试日志**：在一期核心链路（`find`、`openSession`、`addMessage`、`commitSession`、health check）中加入结构化日志，记录请求体、响应状态、关键字段，方便线上定位。

### 接口字段与调试要点

| 接口 | 请求体要点 | 响应要点 | 调试日志要点 |
|---|---|---|---|
| `POST /api/retrieval/search` | `query`、`agent_id`、`session_id`、`limit`、`include_explain`；**不要传 `user_id`** | `result.items` 为数组，元素含 `text`、`score`；`include_debug` 时才含 `kind`/`source`/`evidence_uri`；`result.explain` 记录召回意图 | 打印请求体、返回 item 数量、第一个 item 的字段、explain 概要 |
| `POST /api/sessions/open` | `agent_id` 必填，`session_id`/`run_id`/`metadata` 可选 | `scope.session_id` | 打印原始 session ID 与返回的 EchoMem session ID |
| `POST /api/sessions/{id}/messages` | `role`、`content`；可选 `name`、`metadata` | `message` 对象 | 打印发送消息数、返回 message.id |
| `POST /api/sessions/{id}/commit` | 可传 `metadata`；**不要传 `wait: true`** | `result.commit_id`、`result.archive_id`、`result.status` | 打印 commit_id、archive_id、status |
| `GET /health` | 无 | `status`、`service`、`version` | 打印响应状态与 `status` 字段 |

> 说明：身份字段由后端从 `X-Auth-Key` 推导，请求体中携带 `user_id` 会导致 `INVALID_ARGUMENT` 错误。一期客户端代码中如有条件发送 `user_id` 的分支应一并移除。

- [x] 所有用户可见文案不再出现"OpenViking"。

## 二期：资源与 Skill 管理迁移

### 目标

将资源上传、资源列表、资源删除、Skill 上传、Skill 列表、Skill 删除从 OpenViking 的 fs 操作迁移到 EchoMem 的 `/api/resources` 和 `/api/skills` 服务接口。

### 新增/修改文件

| 文件 | 操作 | 说明 |
|---|---|---|
| `src/panels/resource/import.js` | 修改 | 移除 `tempUpload` 和 `contentAbstract` 轮询；上传时读取文件内容调用 `POST /api/resources`；列表用 `/fs/ls?uri=echo://resources/` |
| `src/panels/resource/manage.js` | 修改 | 删除改用 `DELETE /api/resources/{resource_id}`；移除 `fsRm` 调用；新建文件夹功能隐藏或禁用 |
| `src/panels/skill-store/index.js` | 修改 | 上传时读取 SKILL.md 内容调用 `POST /api/skills`；列表用 `/fs/ls?uri=echo://skills/`；删除改用 `DELETE /api/skills/{name}` |
| `src/services/echomem-client.js` | 新增方法 | 添加 `addResource()`、`deleteResource()`、`addSkill()`、`deleteSkill()` |
| `src/services/openviking-client.js` | 删除 | 二期完成后确认无引用再删除 |

### 接口映射

| 功能 | 原接口 | 新接口 |
|---|---|---|
| 文件临时上传 | `POST /api/v1/resources/temp_upload` | **移除** |
| 添加资源 | `POST /api/v1/resources` | `POST /api/resources` |
| 添加 Skill | `POST /api/v1/skills` | `POST /api/skills` |
| 列出资源 | `GET /api/v1/fs/ls?uri=...` | `GET /fs/ls?uri=echo://resources/` |
| 列出 Skill | `GET /api/v1/fs/ls?uri=...` | `GET /fs/ls?uri=echo://skills/` |
| 读取 Skill 内容 | `GET /api/v1/content/read?uri=...` | `GET /fs/read?uri=echo://skills/{name}/SKILL.md` |
| 删除资源 | `DELETE /api/v1/fs?uri=...` | `DELETE /api/resources/{resource_id}` |
| 删除 Skill | `DELETE /api/v1/fs?uri=...` | `DELETE /api/skills/{name}` |
| 创建目录 | `POST /api/v1/fs/mkdir` | **暂无，UI 隐藏** |
| 内容摘要 | `GET /api/v1/content/abstract` | **移除** |
| 内容概览 | `GET /api/v1/content/overview` | **移除或改用 `/fs/read`** |

### 关键实现点

1. **资源上传**：前端读取 `File` 对象内容（文本文件直接 `file.text()`，二进制文件可考虑 base64），构造请求体 `{content, name, content_type, tags, metadata}`。
2. **Skill 上传**：读取文件文本，解析 frontmatter 得到 `name`，构造请求体 `{data, name, description, tags, allowed_tools}`。
3. **资源删除**：需要把资源 ID 保存下来，不能仅依赖 URI。
4. **目录树风险**：保留目录树展示但后端无写能力，新建文件夹按钮隐藏或置灰。

## 三期：效能统计接入

### 目标

接入 EchoMem 后端 Token 消耗统计，替换 `fetchUsage()` stub；为用户会话 Token 汇总保留展示与状态边界，等待 EchoAgent 提供稳定的汇总接口。

### 实现说明

EchoMem 后端已原生暴露 Prometheus 指标端点 `GET /metrics`，扩展侧直接解析该端点获取 Token 消耗，无需等待后端新增专用 usage 接口。

用户会话统计不再调用迁移前的本地统计服务。当前 `background.js` 的 `fetchStatsSummary` handler 直接返回“不支持”错误，不会调用候选的 OpenView `/v1/stats/summary`。效能页把该状态展示为 `— / 暂不可用`；只有未来接口成功返回数字时，真实 `0` 才展示为 `0`。

### 修改文件

| 文件 | 操作 | 说明 |
|---|---|---|
| `src/services/echomem-client.js` | 修改 | `fetchUsage()` 改为 `GET /metrics`；新增 `fetchMetrics()` 与 Prometheus text 解析器；汇总 router + engine 的 input/output tokens |
| `background.js` | 修改 | `echoMemRequest` 代理同时返回 `data`（JSON）和 `text`（原始响应体），以支持 `/metrics` 纯文本响应；`fetchStatsSummary` 当前返回不支持错误 |
| `src/panels/performance/index.js` | 修改 | `refresh()` 支持部分失败：后端消耗与会话统计互不影响，不可用数据不降级为零 |
| `src/panels/performance/view-state.js` | 新增 | 区分 `available`、`unavailable`、`error`、`hidden`，集中生成展示状态 |
| `src/services/config.js` | 修改 | 新增 `DEFAULT_OPENVIEW_CONFIG`、`getOpenViewConfig()`、`setOpenViewConfig()` |
| `src/services/openview-client.js` | 新增 | 封装 OpenView/EchoAgent 登录并保存会话身份；当前不拉取 stats summary |
| `src/panels/echomem/config.js` | 修改 | 增加 OpenView 服务地址/用户名/密码配置与登录按钮；连接测试、配置保存和登录结果均在对应卡片内反馈 |

### 接口映射

| 功能 | 原接口 | 新接口 |
|---|---|---|
| EchoMem 后端 Token 消耗 | 二期 stub | `GET /metrics`（解析 `echomem_router_llm_input_tokens_total`、`echomem_router_llm_output_tokens_total`、`echomem_engine_llm_input_tokens_total`、`echomem_engine_llm_output_tokens_total`） |
| 用户会话 Token 汇总 | 迁移前本地 `GET /api/stats/summary` | 暂不可用；`/v1/stats/summary` 仅为候选路径，当前未调用 |
| OpenView 登录 | — | `POST /v1/auth/login` |

### 关键实现点

1. **`/metrics` 无需认证**：后端在 auth 检查前直接响应该端点。
2. **Prometheus 文本解析**：在 `echomem-client.js` 内实现轻量解析器，仅提取 4 个 LLM token counter 并求和。
3. **非 JSON 响应兼容**：`background.js` 的 `echoMemRequest` 现在同时返回 `data`（JSON）与 `text`（原始文本），`/metrics` 走 `text` 字段。
4. **统计口径**：后端总消耗 = Router LLM input + Router LLM output + Engine LLM input + Engine LLM output。
5. **部分失败隔离**：performance 面板中，后端消耗与会话统计任一失败不影响另一项展示。
6. **零值语义**：成功返回的零展示为 `0`；不支持、缺失和失败展示为 `—`，并提供对应辅助文案。
7. **完整总量**：只有会话统计和后端统计都可用时才相加；任一缺失时顶部总量展示为 `—`。

### 验收标准

- [x] 效能面板能正确展示 EchoMem 后端 Token 消耗（来自 `/metrics`）。
- [ ] EchoAgent 提供稳定的用户会话 Token 汇总接口与认证契约。
- [x] 汇总接口不可用时，效能页显示 `— / 暂不可用`，不伪装为 `0`。

- [x] 构建通过，`npm run build` 无报错。

## 风险与依赖

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| EchoMem 后端 `/api/retrieval/search` 返回格式与原 `find` 不一致 | 输入联想结果解析错误 | 一期重点测试 recall 返回结构和字段 |
| EchoMem 后端资源服务创建的资源 URI 与目录树展示不一致 | 资源列表显示异常 | 二期优先验证 `/fs/ls?uri=echo://resources/` 的返回 |
| `agent_id` 按平台区分后，后端召回隔离策略未知 | 可能影响召回效果 | 与后端确认 tenant/user/agent 的权限和隔离逻辑 |
