# 周期回顾模块设计

> 相关代码：`src/entry/feedback-summary.js`、`src/services/summary-client.js`、`src/panels/feedback/summary/`

## 目标

在认知反馈中增加独立的“周期总结”视图，按日或按周呈现 EchoMem 已生成的回顾内容。界面强调可读性、时间选择和信息来源，不重新解释、排序或改写后端记忆事实。

## 视图边界

本功能注册到 PR 1 提供的认知反馈公共壳。完整产品可包含三个并列视图：

1. **记忆图谱**：Atom、Entity 及其关系。
2. **情节记忆**：Episode 经历与事件。
3. **周期总结**：Daily/Weekly Summary 的阶段性回顾。

周期总结只在自己的视图内加载、缓存和销毁，不改变图谱或 Episode 状态。其样式通过 `summary-theme.js` 独立注入，不向 Episode 主题文件加入未使用的规则；即使 PR 2 尚未合并，本模块也能与图谱独立工作。

## 数据流程

1. `fetchSummaryList()` 读取后端已有的每日和每周回顾目录。
2. 日期或周选择器只提供后端真实存在的周期。
3. `fetchDailySummary()` / `fetchWeeklySummary()` 读取对应 JSON。
4. `summary-view.js` 管理模式、周期、加载 revision、错误/空状态和清理。
5. `summary-cards.js` 将后端字段映射为可翻阅卡片，不改变字段顺序和语义。

## 信息与交互设计

- 顶部提供“每日回顾 / 每周回顾”切换及可用周期选择器。
- 回顾采用 Wrapped 风格卡片，逐页展示概览、事实、决定、行动项、主题、记忆更新和来源。
- 使用 Swiper 的键盘与无障碍模块；测量异常时降级为可阅读的首卡，不阻塞内容。
- 切换周期时保留当前模式，并仅刷新 Summary 数据。
- 关闭视图时销毁 Swiper、文档级事件和异步 revision。

## 数据保真与错误语义

- 不静默排序、过滤、合并、去重、截断或替换后端 Summary 字段。
- 未知字段保持在原始对象中；视图只读取当前设计明确使用的字段。
- 只有明确表示目录不存在的 404 可映射为空列表。
- 401/403、网络错误、超时和 5xx 必须进入错误/重试界面，不能伪装成“暂无回顾”。
- 迟到响应只有在容器仍连接、状态对象仍相同且 revision 有效时才能更新界面。

## 非目标

- 不修改 Summary 的生成、写入或后端调度。
- 不改变 Episode 或图谱的数据处理。
- 不修改 Episode 的入口、源码或构建产物。
- 不提交记忆花园原型。
- 不在前端生成缺失的日报、周报或默认内容。

## 依赖与兼容性

- 新增 `swiper` 运行时依赖，仅由周期回顾卡片使用。
- 继续使用认知反馈居中浮层、视图切换 revision 和 `_previousOverlay` 恢复机制。
- 保留 Summary 客户端的 HTTP status，供视图区分“确实不存在”和“读取失败”。
- 本 PR 只替换 Summary 入口并生成 `dist/feedback-summary.js`；公共 `dist/content.js` 与 Episode bundle 保持和 PR 1 一致。
- 分支直接基于 PR 1，不包含 PR 2 的任何提交，因此可与 Episode 按任意顺序合并。
