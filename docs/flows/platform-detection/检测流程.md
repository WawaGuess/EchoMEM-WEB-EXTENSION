# 平台检测流程

> 相关代码：`src/core/detection.js`、`src/core/detection-matcher.mjs`
> 配置参考：`docs/reference/平台配置参考.md`

## 概述

EchoMem 扩展按平台执行已配置的主机、路径、标题、DOM 和内容检测。HIGO 额外将主机分为官方可信主机与 localhost/IP 回退主机：公网和内网可信主机不等待 DOM，回退主机使用“品牌信号 + 任一语义 DOM 特征”二次确认。公网标题 `Echo` 和内网标题 `Echo Agent` 都是有效的回退品牌信号。不要求“工作空间图标 + 标题栏菜单”或“输入框 + 发送按钮”这类固定组合。目前已支持 HIGO Office 和 DeepSeek 两个平台。

## 检测架构

### 运行入口

当前内容脚本采用模块化源码 + 构建产物的方式运行：

```text
src/entry/content.js  →  npm run build  →  dist/content.js
```

Chrome 通过 `manifest.json` 加载 `/dist/content.js`。修改 `src/` 下的运行逻辑后，需要执行 `npm run build` 并重新加载扩展。

### 配置结构

```javascript
export const platformRegistry = {
  higo: higoPlatform,
  deepseek: deepseekPlatform
};
```

每个平台配置保存在 `src/platforms/`，配置项包括：

| 配置项 | 说明 |
|--------|------|
| `id` | 稳定平台 ID |
| `name` | 平台展示名称 |
| `detection` | URL、标题、DOM、内容关键字检测配置 |
| `input` | 输入联想和内容插入使用的输入框配置 |
| `headerLauncher` | 可选的 HIGO 标题栏组合标入口配置 |
| `panelHost` | 面板承载方式，统一使用 `overlay` |
| `menuItems` | 当前平台展示的功能面板 ID 列表 |

功能面板使用 `panelRegistry` 注册，平台菜单通过稳定 `panelId` 引用面板：

```javascript
menuItems: [
  { panelId: 'resources' },
  { panelId: 'association' },
  { panelId: 'feedback' },
  { panelId: 'skillStore' },
  { panelId: 'performance' }
]
```

## 检测流程图

```text
检测开始
  └─ 主机与路径边界匹配？
       ├─ 否 → 返回 false
       └─ 是
            ├─ HIGO 官方可信主机 → 不等待 DOM
            ├─ HIGO localhost/IP 回退主机
            │    └─ 品牌词命中 且 任一语义 DOM 命中？
            │         ├─ 否 → 返回 false
            │         └─ 是 → 通过回退身份确认
            └─ 其他平台 → 按配置执行 URL/标题/DOM/内容检测

所有已配置的检测通过 → 返回 true
```

## 检测函数实现

```javascript
function detectPlatformMultiLayer(detection) {
  // 第一层：分级主机信任 + 路径检测
  const trusted = matchesAllowedHostname(
    window.location.hostname,
    detection.trustedHostnames
  );
  const fallback = !trusted && matchesAllowedHostname(
    window.location.hostname,
    detection.fallbackHostnames
  );
  if (!trusted && !fallback) return false;

  if (detection.pathnamePrefixes) {
    const pathMatch = matchesPathnamePrefixes(
      window.location.pathname,
      detection.pathnamePrefixes
    );
    if (!pathMatch) return false;
  }

  // localhost/IP 回退主机需要品牌词和语义 DOM 双重证明
  if (fallback) {
    const identity = detection.fallbackIdentity;
    const pageText = `${document.title}\n${document.body?.innerText || ''}`;
    const brandMatch = identity.titleOrContentKeywords.some(keyword =>
      pageText.toLowerCase().includes(keyword.toLowerCase())
    );
    const domMatch = identity.optionalDomFeatures.some(selector =>
      document.querySelector(selector)
    );
    if (!brandMatch || !domMatch) return false;
  }

  // 兼容尚未迁移的平台
  if (detection.urlPatterns) {
    const urlMatch = detection.urlPatterns.some(pattern =>
      window.location.href.includes(pattern)
    );
    if (!urlMatch) {
      console.log('Claw Extension: 平台检测未通过 - URL不匹配');
      return false;
    }
  }

  // 第二层：页面标题检测
  if (detection.titleKeywords) {
    const titleMatch = detection.titleKeywords.some(keyword =>
      document.title.includes(keyword)
    );
    if (!titleMatch) {
      console.log('Claw Extension: 平台检测未通过 - 标题关键字不匹配');
      return false;
    }
  }

  // 第三层：DOM 特征检测
  if (detection.domFeatures) {
    const { required, optional } = detection.domFeatures;

    // 必须元素全部存在
    if (required && required.length > 0) {
      for (const feature of required) {
        if (!document.querySelector(feature.selector)) {
          console.log(`Claw Extension: 平台检测未通过 - 缺少必要DOM: ${feature.description}`);
          return false;
        }
      }
    }

    // 可选特征至少存在一个
    if (optional && optional.length > 0) {
      const optionalMatch = optional.some(feature =>
        document.querySelector(feature.selector) !== null
      );
      if (!optionalMatch) {
        console.log('Claw Extension: 平台检测未通过 - 无可选DOM特征匹配');
        return false;
      }
    }
  }

  // 第四层：页面内容关键字（如果 body 还未加载，跳过此层）
  if (detection.contentKeywords && document.body) {
    const bodyText = document.body.innerText || '';
    // 如果 body 有内容才检测，无内容时跳过（避免页面加载初期误判）
    if (bodyText.length > 0) {
      const contentMatch = detection.contentKeywords.some(keyword =>
        bodyText.toLowerCase().includes(keyword.toLowerCase())
      );
      if (!contentMatch) {
        console.log('Claw Extension: 平台检测未通过 - 页面内容关键字不匹配');
        return false;
      }
    }
  }

  console.log('Claw Extension: 平台检测全部通过');
  return true;
}
```

## 各层检测说明

### 第一层：站点与路径匹配

| 属性 | 值 |
|------|-----|
| 检测方式 | hostname 分级白名单 + `pathname === prefix` 或 `pathname.startsWith(prefix + '/')` |
| 可信主机 | `echo-agent.online`, `www.echo-agent.online`, `higo.world`, `echo.cn-north-5.myhuaweicloud.com` |
| 回退主机 | `localhost`, `127.0.0.1`, 任意 IPv4；需要额外身份校验 |
| 路径前缀 | `/home`（覆盖 `/home` 及其子路由，不匹配 `/homepage`） |
| 作用 | 快速过滤非 HIGO 页面 |

**示例**：
- ✓ `https://echo-agent.online/home`（可信主机，无需等待 DOM）
- ✓ `https://echo.cn-north-5.myhuaweicloud.com/home`（内网可信主机，标题为 `Echo Agent`）
- ✓ `http://localhost:31010/home`（需品牌词 + 语义 DOM）
- ✓ `http://localhost:31010/home/session/abc123`（需品牌词 + 语义 DOM）
- ✗ `http://localhost:31010/homepage`
- ✗ `http://localhost:31010/search?redirect=/home`
- ✗ `http://localhost:31010/#/home`
- ✗ `http://other-site.com/home`
- ✗ `http://localhost:31010/login`
- ✗ `http://other-site.com/chat`

### 第二层：页面标题关键字

HIGO 公网和内网可信域名不配置全局标题硬门槛。只有 localhost/IP 回退主机使用 `titleOrContentKeywords`，且标题或正文命中任一品牌词即可；其中公网使用 `Echo`，内网使用 `Echo Agent`。

### 第三层：DOM 特征检测

#### 必要元素（required）

HIGO 不配置全局必要 DOM 元素。`.MuiDrawer-root` 和 `.MuiPaper-root` 属于宿主实现细节，不再作为硬门槛。

#### 可选特征（optional）

仅对 localhost/IP 回退主机，至少存在一个：

| 选择器 | 描述 | 对应组件 |
|--------|------|----------|
| `[data-testid="WorkspacesOutlinedIcon"]` | 工作空间导航图标 | 左侧主导航 |
| `[data-testid="MenuOpenIcon"]` | 菜单图标 | 顶部标题栏 |
| `textarea[id^="_r_"]` | React 输入框 | 聊天输入框 |
| `[data-testid="ArrowUpwardIcon"]` | 发送按钮图标 | 消息发送按钮 |

通用 MUI 容器和右侧抽屉不再用于识别平台。官方域名在首屏 DOM 出现前就可确认平台，MutationObserver 只负责等待可挂载的 TitleBar；localhost/IP 则在品牌词和任一语义 DOM 同时出现后通过检测。

### 第四层：页面内容关键字

HIGO 官方域名不配置全局内容硬门槛。localhost/IP 回退主机会把正文与标题合并为品牌身份信号，不要求两者同时匹配。

## 检测重试机制

由于 HIGO Office 是 React 单页应用，DOM 动态加载，检测时可能 DOM 尚未渲染完成。因此检测失败时不缓存 `null` 结果，允许 MutationObserver 在下次 DOM 变化时重新检测：

```javascript
function addCustomButtons() {
  // 如果还没有检测到平台，先进行检测
  // 注意：不缓存检测失败的结果，因为 DOM 可能是动态加载的
  if (!currentPlatform) {
    const detected = detectPlatform();
    if (detected) {
      currentPlatform = detected;
      console.log('Claw Extension: Platform detected -', currentPlatform.config.name);
    } else {
      return;  // 不设置 currentPlatform，下次 DOM 变化时重试
    }
  }
  // ... 后续标题栏入口注入逻辑
}
```

## 持续监听机制

使用 MutationObserver 持续监听 DOM 变化，确保在动态加载完成后注入按钮：

```javascript
const lifecycle = createDomLifecycle({
  onDomChange: refreshContentScriptMount,
  delay: 120
});

lifecycle.start();
```

`refreshContentScriptMount()` 负责尝试注入 EchoMem 入口，并绑定面板内的导航事件。HIGO 只注入一个网页入口：

- 顶部标题栏的“图形 + EchoMem”组合标，不依赖会话输入框；优先通过菜单图标或标题文本识别完整标题栏，再动态读取右侧第一个可见控件的位置并紧贴其左侧。入口脱离 flex 布局流，避免挤偏居中标题；工作空间页没有右侧控件时则直接占用空占位并贴到最右侧，不保留中间空档。无法识别标题栏时，才回退到分享按钮或右箭头锚点。

标题栏组合标和浏览器工具栏图标都打开同一个网页 overlay。输入框仍用于输入联想和内容插入，但附近不再注入 EchoMem 按钮。
