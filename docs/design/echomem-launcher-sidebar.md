# EchoMem 单入口按钮与右侧功能导航设计

## 1. 背景

旧版 EchoMem Web Extension 会在聊天输入框下方注入 4 个功能按钮：

- 资源管理
- 输入联想
- 认知反馈
- skill商店

新的交互目标是将输入区的 4 个按钮收敛为 1 个入口按钮：

- 按钮文字：`EchoMem`
- 位置：聊天框外部上方
- 点击行为：打开右侧侧边栏，侧边栏中展示当前 4 个功能选项，并新增 1 个选项「效能」

## 2. 设计目标

1. 输入区只出现一个 `EchoMem` 入口，降低聊天框周边视觉占用。
2. 入口位于聊天框外部上方，不占用输入框内部空间。
3. 点击 `EchoMem` 后，右侧面板先进入功能导航首页，而不是直接进入某个功能。
4. 功能导航首页展示 5 个选项：资源管理、输入联想、认知反馈、skill商店、效能。
5. 点击任一选项后，在同一个右侧面板内展示对应功能内容。
6. 尽量复用现有面板系统和已有 4 个功能面板，新增「效能」作为独立面板内容。

## 4. 页面布局

### 4.1 入口按钮位置

入口按钮放在聊天输入框外部上方，作为输入框的相邻工具行。

```
┌──────────────────────────────────────────┐
│ EchoMem                                  │
└──────────────────────────────────────────┘
┌──────────────────────────────────────────┐
│  用户输入内容区域                         │
│                                          │
│                         [发送按钮]       │
└──────────────────────────────────────────┘
```

实现时建议：

- 创建 `.claw-echomem-launcher-bar` 作为输入框外部相邻元素。
- 默认插入到输入框容器之前：`insertPosition: 'before'`。
- launcher bar 背景跟随页面或输入区背景，按钮本体保持浅色可读。
- 如果平台输入框高度较低，按钮可以压缩为高度 `24px` 到 `28px` 的轻量样式。

### 4.2 入口按钮样式

建议使用克制的文字按钮样式，避免像功能按钮组一样抢占空间。

```css
.claw-echomem-launcher-bar {
  display: flex;
  justify-content: flex-start;
  align-items: center;
  padding: 0 12px 8px;
}

.claw-echomem-launcher {
  height: 28px;
  padding: 0 10px;
  border: 1px solid rgba(0, 0, 0, 0.12);
  border-radius: 6px;
  background: #fff;
  color: #1f2937;
  font-size: 12px;
  font-weight: 600;
  cursor: pointer;
}
```

深色背景或透明背景页面需要动态读取输入区背景色，沿用现有 `getBackgroundColor` 思路，但动态背景只应用到 launcher bar，不直接应用到按钮本体，避免深色页面里按钮不可读。

## 7. 配置模型调整

旧版平台配置使用 `buttonBar` 和 `buttons` 描述多按钮栏。当前实现已改为 `launcher` 和 `menuItems`。

```javascript
launcher: {
  text: 'EchoMem',
  containerSelector: '.MuiPaper-root',
  validateSelectors: {
    textarea: 'textarea[id^="_r_"]',
    sendButton: '[data-testid="ArrowUpwardIcon"]'
  },
  style: {
    display: 'flex',
    padding: '0 12px 8px'
  },
  insertPosition: 'before'
},
menuItems: [
  { text: '资源管理', panel: '资源管理' },
  { text: '输入联想', panel: '输入联想' },
  { text: '认知反馈', panel: '认知反馈' },
  { text: 'skill商店', panel: 'skill商店' },
  { text: '效能', panel: '效能' }
]
```

当前运行入口仍兼容读取 `buttonBar`，但正式配置应优先使用 `launcher/menuItems`。

## 8. 代码影响范围

预计需要调整或新增以下模块：

| 文件 | 调整内容 |
|------|----------|
| `src/core/buttons.js` | 从注入按钮组改为注入 `EchoMem` 单入口；点击打开功能导航首页 |
| `src/core/panel.js` | 复用现有 `openCustomPanel()`；详情页继续使用返回按钮能力 |
| `src/panels/index.js` | 注册新增「效能」面板；提供 EchoMem 导航首页内容 |
| `src/panels/performance.js` | 新增「效能」面板内容 |
| `src/platforms/higo.js` | 将 4 个按钮配置调整为 `EchoMem` launcher 与 5 个菜单项 |
| `src/platforms/deepseek.js` | 同步配置；无原生右侧栏时继续使用 overlay 模式 |
| `content.js` | 当前 Manifest 实际加载的运行入口，需要同步相同逻辑 |

> 当前项目没有构建步骤，Chrome 通过 `manifest.json` 直接加载根目录的 `content.js`。`src/` 目录是模块化源码镜像；修改运行行为时，需要优先修改 `content.js`，并同步维护 `src/` 中对应模块，或后续明确切换到构建/打包流程。

## 9. 兼容策略

### HIGO Office

- 使用现有 `sidebar` 模式，点击 `EchoMem` 替换右侧侧边栏内容。
- 关闭面板后恢复原始右侧栏。
- 功能详情页点击返回，回到 `EchoMem` 功能导航首页。

### DeepSeek

- 页面没有可替换的右侧业务侧栏，继续使用现有 `overlay` 模式。
- `EchoMem` 入口仍位于输入框外部上方。
- 点击后从右侧滑出 EchoMem 功能导航浮层。

## 10. 交互验收标准

1. 支持平台页面中，聊天输入框附近只出现 1 个 `EchoMem` 按钮。
2. 页面不再显示旧的 4 个横向功能按钮。
3. `EchoMem` 按钮位于聊天框外部上方，并且不遮挡输入文字和发送按钮。
4. 点击 `EchoMem` 后，右侧面板打开并展示 5 个选项。
5. 5 个选项分别为：资源管理、输入联想、认知反馈、skill商店、效能。
6. 点击前 4 个选项后，能进入当前已有对应面板。
7. 点击「效能」后，能进入效能面板。
8. 详情页点击返回后，回到 EchoMem 功能导航首页。
9. 点击关闭后，HIGO 恢复原右侧栏，DeepSeek 移除浮层。
10. 多次页面动态更新后不会重复注入多个 `EchoMem` 按钮。

## 11. 实施建议

建议分两步实现：

1. 先完成结构改造：单入口按钮、功能导航首页、5 个菜单项、返回链路。
2. 再完善「效能」真实数据采集；首版可以先使用空状态和占位统计。

这样可以先稳定新的交互形态，再逐步补齐效能模块的数据能力。
